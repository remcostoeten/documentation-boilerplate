---

Run them with `bun run <name>`. `bun dev`, `bun test` and `bun start` work without `run`.

| Script           | Runs                                                       |
| ---------------- | ---------------------------------------------------------- |
| `dev`            | The dev server on `localhost:3000`                         |
| `start`          | The production server, after a build                       |
| `build`          | Changelog sync, link check, then `next build`              |
| `typecheck`      | Regenerates `.source` and route types, then `tsc --noEmit` |
| `test`           | `bun test`, the changelog and config tests                 |
| `check`          | Format check and lint through `vp check`                   |
| `lint`           | `vp lint`                                                  |
| `lint:fix`       | `vp lint --fix`                                            |
| `format`         | `vp fmt`, which writes changes                             |
| `format:check`   | `vp fmt --check`, which only reports                       |
| `sync:changelog` | Writes the changelog pages                                 |
| `check:links`    | Checks internal links in the content                       |
| `postinstall`    | `fumadocs-mdx`, which generates `.source`                  |

## dev and start

Both go through `scripts/serve.ts`, which finds a free port starting at `PORT` or 3000, up to 50 ports on, and starts `next dev` or `next start` on it with Bun. `dev` also syncs the changelog first and watches the changelog files. In a terminal, `o` opens the browser and `q` quits.

## build

```bash
bun run sync:changelog && bun run check:links && bun --bun next build
```

The build stops at the first step that fails. Broken internal links therefore fail the build before Next.js starts.

## check:links

`scripts/check-links.ts` reads every page in `content/docs`, outside code blocks, and checks each link that starts with `/docs` or `#`:

- The target page exists.
- When the link has an anchor, the target page has a heading that produces it.

It prints each broken link with the file and the reason, and exits with 1. External links are not checked.

## sync:changelog

Writes `content/docs/<page>.mdx` for each entry in `site.changelogs`. See [Publishing a changelog](/docs/guides/changelog).

## typecheck and .source

`.source` is generated by `fumadocs-mdx` and holds the typed collections the site imports. `bun install` creates it. After you change `source.config.ts`, run `bun run typecheck` or restart `bun dev` to regenerate it.

## CI

`.github/workflows/ci.yml` runs on every pull request and on pushes to `master`. It installs with `--frozen-lockfile`, then runs `bun run check`, `bun test`, `bun run typecheck` and `bun run build`, with a full git history so last updated dates work.
