Every fenced code block in an `.mdx` file is highlighted on the server with Shiki, so no JavaScript is shipped for the highlighting. Write a normal Markdown fence, put the language after the opening backticks and add options after it. Each section below shows the Markdown you write, then the result.

## Syntax

````md title="Anatomy of a fence"
```language option title="Header text"
code
```
````

- `language` picks the grammar, for example `ts`, `tsx`, `bash`, `json`, `css` or `txt`.
- Options are single words such as `lineNumbers`, `noCopy` or `twoslash`.
- `title="..."` is a quoted option that adds a file header.
- Options go on the opening line only, in any order. Line level effects go in comments inside the code.

## File header

A `title` adds a header with the language label and a copy button.

````md title="page.mdx"
```ts title="src/shared/config/site.ts"

  name: "Docs",
  url: "http://localhost:3000",
};
````

## Line notation

Notation is a comment at the end of a line. The comment is removed from the output and the effect applies to that line. Use the comment syntax of the language, so `//` for TypeScript and `#` for Bash.

| Comment                  | Effect                                 |
| ------------------------ | -------------------------------------- |
| `// [!code highlight]`   | Tints the line                         |
| `// [!code word:loader]` | Highlights every `loader` in the block |
| `// [!code ++]`          | Marks the line as added                |
| `// [!code --]`          | Marks the line as removed              |
| `// [!code focus]`       | Dims every line that is not focused    |

### Highlighted lines

````md title="page.mdx"
```tsx title="src/app/docs/layout.tsx"
export default function Layout({ children }: { children: ReactNode }) {
  const tree = source.getPageTree(); // [!code highlight]
  return <DocsLayout tree={tree}>{children}</DocsLayout>;
}
````

## Options

| Option           | Effect                                                |
| ---------------- | ----------------------------------------------------- |
| `title="text"`   | Header with the language and a copy button            |
| `lineNumbers`    | Number the lines from 1                               |
| `lineNumbers=12` | Number the lines from 12                              |
| `noCopy`         | Remove the copy button                                |
| `tab="Name"`     | Group with the neighbouring blocks into tabs          |
| `twoslash`       | Type check the snippet and add hover types, see below |

### Tabs

### Result and usage

To show a block and the Markdown that produces it in one place, put both in `Tabs`. The first tab holds the rendered block, the second holds the fence in a four backtick `md` block so the inner fence is shown as text.

<Tab value="Result">

```ts title="src/shared/config/site.ts" lineNumbers

  name: "Docs",

};
```

</Tab>

Leave a blank line after each `Tab` opening tag and before its closing tag, or the content is parsed as inline text. Give related demos the same `groupId` and the reader's choice carries to every one of them. ## TypeScript hover types

Add the `twoslash` option to a `ts` or `tsx` fence and the snippet is type checked with the TypeScript compiler at build time. Hover an identifier to see its type and JSDoc, as in an editor.

````md title="page.mdx"
```ts twoslash title="src/shared/config/site.ts"
import { site } from "@/shared/config/site";

const accent = site.theme.accent;
const pages = site.changelogs.map((changelog) => changelog.page);
```
````

```ts twoslash title="src/shared/config/site.ts"
import { site } from "@/shared/config/site";

const accent = site.theme.accent;
const pages = site.changelogs.map((changelog) => changelog.page);
```

`@/` resolves to `src`, so a snippet can import the real modules of this project and hovers show their real types. The compiler options live under `twoslashOptions` in `source.config.ts`.

## Type queries

A `^?` marker prints the type of the token above it under the line. Put the caret under the first character of the token.

````md title="page.mdx"
```ts twoslash
import { site } from "@/shared/config/site";

const footer = site.pageFooter;
//    ^?
```
````

```ts twoslash
import { site } from "@/shared/config/site";

const footer = site.pageFooter;
//    ^?
```

## Completions

A `^|` marker shows the completion list at that position. Incomplete code needs `@noErrors`.

````md title="page.mdx"
```ts twoslash
// @noErrors
import { site } from "@/shared/config/site";

site.pageFooter.
//              ^|
```
````

```ts twoslash
// @noErrors
import { site } from "@/shared/config/site";

site.pageFooter.
//              ^|
```

## Expected errors

An error listed in `@errors` is shown under its line. Any other type error fails the build, so a snippet cannot drift from the types it documents.

````md title="page.mdx"
```ts twoslash
// @errors: 2322
import { site } from "@/shared/config/site";

site.pageFooter.editLink = "yes";
```
````

```ts twoslash
// @errors: 2322
import { site } from "@/shared/config/site";

site.pageFooter.editLink = "yes";
```

## Hide setup code

Everything above `// ---cut---` is type checked but not shown. Use it for imports and fixtures that would distract from the point.

````md title="page.mdx"
```ts twoslash
import { site } from "@/shared/config/site";
// ---cut---
const titles = site.changelogs.map((changelog) => changelog.title);
```
````

```ts twoslash

// ---cut---

```

## Mock a module

For a package that is not installed here, declare a stand-in in a `.d.ts` file with `// @filename:`. The mock is checked with the snippet and not shown.

````md title="page.mdx"
```ts twoslash
// @filename: acme-docs.d.ts
declare module "acme-docs" {
  export type DocsConfig = {
    /** Shown in the header and the browser tab. */
    name: string;
    url: string;
  };
  export function defineConfig(config: DocsConfig): DocsConfig;
}

// @filename: index.ts
// ---cut---
import { defineConfig } from "acme-docs";

export default defineConfig({
  name: "Acme",
  url: "https://acme.dev",
});
```
````

```ts twoslash
// @filename: acme-docs.d.ts
declare module "acme-docs" {
  export type DocsConfig = {
    /** Shown in the header and the browser tab. */
    name: string;
    url: string;
  };
  export function defineConfig(config: DocsConfig): DocsConfig;
}

// @filename: index.ts
// ---cut---
import { defineConfig } from "acme-docs";

export default defineConfig({
  name: "Acme",
  url: "https://acme.dev",
});
```

Any `// @name: value` line that names a TypeScript compiler option, such as `// @strict: false`, applies to that block only. Results are cached in `.next/cache/twoslash`.

## Tabs as components

````mdx title="page.mdx"
  </CodeBlockTab>
  <CodeBlockTab value="npm">

  </CodeBlockTab>
</CodeBlockTabs>
````

## Popups

`Popup`, `PopupTrigger` and `PopupContent` are the pieces Twoslash uses for its hover cards. They are registered for MDX, so you can use them for a hover or tap card around any text, without a code block.

```mdx title="page.mdx"
<Popup>
  <PopupTrigger>`site.askAI`</PopupTrigger>
  <PopupContent>Set to `null` to turn the chat off.</PopupContent>
</Popup>
```
