Four things sit under the content of each docs page: the feedback widget, the edit link, the last updated date and the previous and next links.

## Feedback widget

The widget asks "Was this page helpful?" with a Yes and a No button.

1. Clicking a button sends the rating at once.
2. A text box then offers an optional note, up to 1000 characters. Sending it submits the same rating again with the note.
3. After a note is sent the widget is replaced by a thank you.

Each submission goes through the server action `submitFeedback` in `src/modules/feedback/server/submit-feedback.ts`. It validates the input with Zod and passes it to `handleFeedback`. If that throws, the widget shows "Feedback could not be saved. Try again later." and logs the error on the server.

The submitted data is:

<TypeTable
  type={{
    url: { type: "string", description: "The page path, starting with a slash.", required: true },
    rating: {
      type: '"helpful" | "not-helpful"',
      description: "The button that was clicked.",
      required: true,
    },
    message: {
      type: "string",
      description: "The optional note, trimmed, at most 1000 characters.",
    },
  }}
/>

### Where feedback goes

By default `handleFeedback` only logs a line to the server console:

```txt
[feedback] {"url":"/docs/guides/theming","rating":"helpful","at":"2026-10-18T09:12:44.000Z"}
```

Replace the body of the function in `src/modules/feedback/server/feedback-handler.ts` to store it somewhere. The rest of the widget does not change.

```ts title="src/modules/feedback/server/feedback-handler.ts"
export async function handleFeedback(feedback: Feedback) {
  await fetch(process.env.FEEDBACK_WEBHOOK_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ ...feedback, at: new Date().toISOString() }),
  });
}
```

<Callout type="warn" title="No protection by default">
  The action accepts any well formed submission and has no rate limit. Add one in `handleFeedback`
  before connecting it to anything that costs money or notifies people.
</Callout>

### Turning it off

Set `pageFooter: { feedback: false, ... }` in `site.ts`. The widget is removed from every page and the server action stays unused.

## Edit link

"Edit this page on GitHub" opens the page's source file on GitHub. The URL is the repository, the branch and `site.contentDir` followed by the page path, built by `repositoryFileUrl`.

| To                            | Do this                                             |
| ----------------------------- | --------------------------------------------------- |
| Hide it on every page         | `pageFooter: { editLink: false, ... }` in `site.ts` |
| Hide it on one page           | `editUrl: false` in the frontmatter                 |
| Point one page somewhere else | `editUrl: https://...` in the frontmatter           |
| Change the repository         | `repository` and `branch` in `site.ts`              |

The link is also hidden when the site has no repository. Pages generated by the changelog sync set `editUrl` to their source file. See [Publishing a changelog](/docs/guides/changelog).

## Last updated

The date is the last commit that touched the page's file, shown in UTC. Turn it off for every page with `pageFooter: { lastUpdated: false, ... }`. It is hidden for a page with no git history, which is also the case in a checkout with `--depth 1`.

When neither the edit link nor the date has anything to show, the footer is not rendered.

## Previous and next links

The links to the neighbouring pages come from the sidebar order. Hide them on every page with `pageFooter: { prevNext: false, ... }` in `site.ts`.
